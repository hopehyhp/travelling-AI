# 旅行智能化逻辑设计

## 1. 总体思路

当前项目已经具备推荐算法基础。新的智能化能力增强不改变核心结构，而是增加“真实环境上下文输入层”，让 AI 能在生成建议时更加贴合真实世界。

系统输入包括：

- 用户偏好：目的地、日期、预算、人数、同行人、旅行目的
- 上下文数据：天气、地理位置、景点分布
- 业务规则：预算控制、出行时间、季节适宜性

系统输出包括：

- 推荐行程
- 智能天气适配建议
- 地图视图
- 旅行提醒和风险提示

## 2. 核心决策逻辑

### 2.1 天气优先级

1. 如果用户填写了出发日期，则获取对应日期的天气数据
2. 如果日期在最佳出行窗口内，则增加推荐权重
3. 如果天气为雨天或极端高温，则优先推荐室内景点和适当调整时间
4. 如果用户更偏户外体验，则在天气不佳时提示替代方案

### 2.2 地图优先级

1. 根据目的地查询经纬度
2. 使用地图定位中心点
3. 在目的地附近进行关键景点标注
4. 将推荐的旅游点和地图位置关联

### 2.3 AI Prompt 注入

AI Prompt 中增加以下字段：

- destinationName
- startDate
- weatherSummary
- temperatureRange
- precipitationRisk
- mapHighlights
- userPurpose
- budget
- people
- companion

生成逻辑根据这些字段输出：

- 每日安排
- 最佳游玩时间
- 备用方案
- 穿衣、装备、天气解释

## 3. 关键异常处理

- 未获取到天气：返回本地季节建议
- 未获取到地图坐标：显示“地图暂不可用”
- API 请求超时：继续显示原有行程
- 目的地不明确：使用用户输入的文本值作为查询参数

## 4. 用户体验准则

- 不让外部 API 失败直接破坏整个旅行体验
- 数据展示必须有明显可读性
- 动态提示与结构化建议优先于冗长解释

## 5. 扩展方向

- 连接交通路线 API
- 增加酒店和餐饮推荐
- 增加用户偏好长期记忆
- 增加“油价/天气风险/拥堵指数”能力
